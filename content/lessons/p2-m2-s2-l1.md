# Explicar la predicción y servirla

Un diagnóstico con una probabilidad del 0,93 es más fácil de aceptar si se puede ver qué parte de la hoja influyó. CropEye agrega esa capa con Grad-CAM, una técnica que produce un mapa de calor sobre las regiones que más aportaron a la clase elegida. Explicar no hace que el modelo sea correcto, pero permite que una persona detecte cuándo la decisión se apoya en algo absurdo.

## Qué mira Grad-CAM

El ensemble combina tres arquitecturas basadas en transformers de visión. Grad-CAM sobre la penúltima capa de bloques calcula el gradiente de la clase predicha respecto de los tokens de esa capa y lo proyecta como un mapa espacial. El resultado no es una segmentación precisa: es una zona caliente que indica dónde se concentró la evidencia. En la práctica, alcanza para verificar si el modelo mira la lesión o el fondo.

```text
imagen → filtro de hoja → ensemble → clase + confianza
                              ↓
                     Grad-CAM (penúltimo bloque)
                              ↓
                     PNG en base64 → respuesta HTTP
```

## La API de inferencia

El servicio vive en el repositorio `cropeye-ia` y expone dos rutas mínimas. `GET /salud` responde si el proceso está vivo y los modelos cargados. `POST /analisis` recibe una imagen en multipart y, opcionalmente, el cultivo, y devuelve la clasificación completa.

```bash
curl -X POST http://localhost:8000/analisis \
  -F "image=@hoja.jpg" \
  -F "crop=tomate"
```

La respuesta incluye la clase, el nombre legible, la confianza, el campo `confiable`, la imagen `gradcam_png` codificada en base64, el modelo utilizado y los milisegundos que tardó. La app consume ese contrato directamente. Como el backend no participa, la API de inferencia quedó expuesta sin autenticación ni cuotas, un punto que se retoma en la ruta 5.

## El costo de explicar

Grad-CAM agrega cómputo y peso a la respuesta. Un PNG en base64 crece alrededor de un tercio respecto del binario, y la app debe decodificarlo antes de dibujarlo. En 89,2 ms por fotografía hay margen suficiente, pero el sobrecosto importa si algún día se procesan lotes.

También hay un costo de interpretación. Un mapa de calor puede verse convincente y estar mal: si el modelo aprendió a reconocer el fondo del invernadero, el mapa señalará esa zona con total seguridad. La explicación no valida la predicción por sí sola; solo la hace auditable.

:::note
La mejor forma de usar Grad-CAM es comparar: si dos versiones del modelo aciertan la misma clase pero miran regiones distintas, probablemente una esté usando un atajo. La explicación sirve para diagnosticar el modelo, no solo para decorar la pantalla.
:::

## Del contrato al producto

La API de inferencia es la frontera más estable del proyecto: dos endpoints, un formato de respuesta y una responsabilidad clara. Esa simplicidad es una ventaja y una trampa. Es ventaja porque permite cambiar el modelo sin tocar a los consumidores; es trampa porque invita a saltarse el backend, que es exactamente lo que ocurrió.
