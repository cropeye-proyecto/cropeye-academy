# La frontera entre backend e IA

El backend y la API de inferencia son dos sistemas con ciclos de vida distintos. Uno cuida usuarios, permisos y persistencia; el otro carga modelos pesados y responde en milisegundos. Si el backend conociera los detalles internos del modelo, cualquier cambio en la IA obligaría a tocar el dominio. El adaptador existe para evitar eso.

## Una sola puerta

En `cropeye-backend`, el archivo `app/services/inference_cropeye.py` concentra toda la comunicación con la API de inferencia. El resto del backend no sabe que existe un ensemble, ni cuántos modelos lo componen, ni cómo se calcula Grad-CAM. Solo conoce una operación: analizar una imagen.

```text
app/services/inference_cropeye.py

  entrada   → bytes de la imagen + cultivo opcional
  salida    → clase, nombre, confianza, confiable, gradcam_png, model, ms
  errores   → timeout, conexión rechazada, respuesta inválida
```

Ese aislamiento tiene un nombre en arquitectura: capa anticorrupción. Su función es traducir el lenguaje de un sistema externo al lenguaje del dominio propio. Cuando la API de inferencia cambie de versión, el adaptador absorbe la diferencia; el servicio de análisis, los endpoints y las pruebas del dominio no deberían enterarse.

El filtro de hoja, en cambio, vive del lado de la IA. El adaptador no decide si la imagen sirve: recibe la decisión ya tomada y la traduce a un estado del análisis.

## Traducir también los errores

Un adaptador no solo traduce respuestas exitosas. La API de inferencia puede tardar demasiado, quedarse sin memoria, devolver un JSON incompleto o rechazar la imagen por no contener una hoja. Cada uno de esos casos debe convertirse en un estado distinto del análisis: RECHAZADO cuando la respuesta es una decisión de negocio, ERROR cuando es una falla técnica.

Si el adaptador deja escapar una excepción cruda, el backend responde un error 500 sin contexto y el cliente no puede distinguir «la foto no sirve» de «el servicio se cayó». La traducción de errores es tan importante como la de datos.

:::warning
El repositorio `cropeye-ia` ignora la carpeta `models/`, que no está incluida en el clon. Sin los pesos, el servicio no puede predecir: hay que obtenerlos por fuera del repositorio. Cualquier promesa de «clonar y ejecutar» choca con ese detalle.
:::

## Lo que el adaptador no arregla

Un adaptador reduce el acoplamiento de código, no el acoplamiento operativo. El backend sigue dependiendo de que la API de inferencia esté disponible, tenga capacidad y responda a tiempo. Tampoco resuelve la seguridad entre servicios: la API de inferencia no exige autenticación, así que cualquiera que alcance el puerto 8000 puede usarla.

La tentación es agregar reintentos automáticos y dar por cerrado el problema. Los reintentos ayudan con fallas transitorias y empeoran las fallas por saturación: si el servicio está al límite, multiplicar las llamadas lo hunde más rápido. Un adaptador maduro combina timeout, reintento acotado con espera creciente y un límite de concurrencia.

## El valor de una frontera explícita

La frontera también sirve para razonar sobre el negocio. Si mañana el modelo agrega una clase nueva, el adaptador sigue devolviendo los mismos campos y el backend solo necesita actualizar su catálogo. Si el modelo cambia de proveedor, el adaptador es el único archivo que se reescribe.

> **Para llevarte:** con el backend entendido, la ruta 4 cruza al cliente. La aplicación móvil es quien decide qué imagen llega a esta frontera y cómo se presenta lo que devuelve.
