# Comunicar incertidumbre sin confundir

La pantalla de resultado es el punto donde el modelo se convierte en una decisión humana. CropEye muestra la clase detectada, el nivel de confianza, la marca `confiable` y una imagen Grad-CAM con la zona que influyó. Cada uno de esos elementos puede informar o puede inducir a error, según cómo se presente.

## Qué recibe la app

La respuesta de la API de inferencia incluye la clase, el nombre legible, la confianza, el campo `confiable`, el PNG de Grad-CAM, el modelo y los milisegundos. La app no recalcula nada: presenta lo que recibe. Esa separación es correcta, pero traslada toda la responsabilidad de la comunicación al diseño de la pantalla.

```text
clase:       etiqueta del catálogo
confianza:   probabilidad de la clase elegida (0 a 1)
confiable:   true si la confianza supera el umbral de 0,60
gradcam_png: mapa de calor codificado en base64
```

## La probabilidad no es una promesa

Un 87 % de confianza no significa «87 % de probabilidad de que esta planta tenga esta enfermedad». El número mide cómo se comportó el modelo frente a imágenes parecidas, no una certeza sobre el caso individual. Presentarlo como un porcentaje grande y acompañarlo de un ícono verde invita a leerlo como un diagnóstico confirmado.

La app puede mostrar el número, pero necesita contexto. Una escala cualitativa —alta, media, baja— con una explicación breve comunica mejor que cuatro decimales. Y cuando `confiable` es falso, la pantalla no debería mostrar una clase como si fuera un resultado: corresponde indicar que no hay evidencia suficiente.

:::warning
Si la interfaz usa el mismo color y el mismo ícono para una respuesta confiable y una respuesta rechazada, el usuario recordará la etiqueta y olvidará la advertencia. El estado de rechazo debe verse distinto, no como un detalle al pie.
:::

## La clase «Otra»

«Otra» no es una enfermedad: es la salida que el sistema usa cuando ninguna clase supera el umbral. En la evaluación de campo, este mecanismo rechaza el 74 % de las imágenes desconocidas. Para el usuario, eso significa que una parte de las fotos no devolverá diagnóstico, y la app debe explicar por qué sin sonar a error.

La tentación es esconder esos casos o forzar la mejor clase disponible. Ambas opciones mejoran la sensación de utilidad y empeoran la seguridad. Un sistema que admite no saber es más confiable que uno que siempre responde.

## Grad-CAM como apoyo, no como prueba

El mapa de calor ayuda a verificar que el modelo miró la lesión y no el fondo. Pero también puede verse convincente y estar equivocado: si el modelo aprendió un atajo, el mapa resaltará el atajo con total seguridad. La explicación debe presentarse como una ayuda para la revisión, no como una validación.

## La tensión de la confianza

Mostrar demasiada incertidumbre paraliza; mostrar demasiada certeza engaña. El equilibrio depende del usuario: un agrónomo puede interpretar un porcentaje y un rechazo; un productor sin formación necesita una recomendación clara, incluida la de consultar a un especialista cuando el sistema no responde.
