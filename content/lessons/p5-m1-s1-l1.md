# Dónde vive cada responsabilidad

El informe del proyecto dibuja una topología lineal: la aplicación envía la imagen al backend, el backend la reenvía a la API de inferencia y devuelve el resultado. Ese dibujo no es un capricho: cada salto tiene una responsabilidad distinta y, juntos, convierten una predicción en un servicio.

## El dibujo

```text
cropeye-app  ──HTTP──>  cropeye-backend :8100  ──HTTP──>  cropeye-ia :8000
   captura                 identidad y datos               modelo y Grad-CAM
```

En el primer salto, el backend autentica al usuario, valida la petición, registra el análisis en estado PENDIENTE y guarda la imagen. Después llama a la API de inferencia y, cuando recibe la respuesta, actualiza el estado, guarda el resultado y deja el rastro en la auditoría.

El segundo salto es deliberadamente tonto. La API de inferencia no sabe quién hizo la consulta ni cuántas veces la hizo: recibe bytes y devuelve una clasificación. Su virtud es la ignorancia del contexto; su límite, la misma.

## Por qué el backend va en el medio

Poner al backend en el medio permite cuatro cosas que la app no puede resolver sola. Primero, **identidad**: sin un usuario autenticado no hay forma de limitar el uso ni de atribuir un análisis. Segundo, **persistencia**: el historial deja de depender de la memoria del teléfono. Tercero, **auditoría**: cada cambio de estado queda registrado. Cuarto, **protección**: el backend puede aplicar cuotas y validaciones antes de gastar cómputo en el modelo.

También desacopla la evolución. Si mañana se reemplaza el ensemble, la app no cambia; si se agrega una nueva clase, el catálogo del backend se actualiza. La app sigue hablando el mismo idioma.

## El costo del salto extra

Cada salto agrega latencia, un punto de falla y configuración. La inferencia tarda 89,2 ms, pero el recorrido completo incluye autenticación, escritura en base de datos y almacenamiento de la imagen. En una red móvil, el tiempo de subida suele pesar más que el modelo.

La topología también obliga a que el backend esté disponible para cualquier diagnóstico. Si el backend cae pero la API de inferencia sigue viva, el sistema documentado no responde. Es una dependencia que se acepta a cambio de control.

:::note
Una regla para leer topologías: cada flecha debería corresponder a un contrato y a un responsable. Si una flecha no tiene dueño claro, probablemente sea un atajo que alguien tomó para evitar configurar algo.
:::

## El dibujo y la realidad

Hasta aquí, el diseño. En la implementación, la aplicación se conecta directamente a `10.0.2.2:8000` y el backend escucha en 8100 sin recibir tráfico de la app. El dibujo describe lo que el sistema debería ser; el código describe lo que es. Esa distancia es el tema de la siguiente lección.
